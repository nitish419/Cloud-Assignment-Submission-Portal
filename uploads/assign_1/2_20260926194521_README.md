# Cloud-Based Student Assignment Submission & Feedback Portal

A cloud-computing course project: students submit assignments, teachers grade
and give feedback, all through a REST API backed by a cloud-style database
and object storage layer.

> **Build tier:** Option A (beginner/local) — Flask + SQLite + local-disk
> object storage, but written with the same *abstractions* a cloud
> (Firebase/Supabase/AWS) version would use, so upgrading later is a
> config change, not a rewrite. See "Upgrading to a real cloud backend" below.

## 1. Problem it solves

Paper/email-based assignment submission is hard to track, easy to lose, and
gives no central view of deadlines, late submissions, or feedback. This
portal centralizes assignment creation, submission, grading, and feedback
behind role-based accounts, the same pattern used by real LMS platforms
(Canvas, Google Classroom, Moodle).

## 2. Cloud computing concepts demonstrated

| Concept | Where it appears |
|---|---|
| Cloud Database | `models.py` + `SQLALCHEMY_DATABASE_URI` — swap SQLite for Postgres with one env var |
| Object Storage | `cloud/storage_service.py` — files stored by key, never as DB blobs |
| REST API | `routes/*.py` — versioned, resource-based `/api/...` endpoints |
| Authentication | `auth_utils.py` — password hashing + signed JWT (mirrors Firebase/Cognito) |
| Authorization / RBAC | `role_required()` decorator on every teacher-only route |
| Client-Server Architecture | static frontend calls backend only via REST, never touches DB/storage directly |
| Environment Variables & Secrets | `config.py` + `.env.example` — no secret is hardcoded |
| Input Validation | file type/size checks, marks-range checks, deadline parsing |
| Logging/Error Handling | JSON error responses with correct HTTP status codes on every route |
| Scalability path | storage/db access is abstracted so it can move to S3 + managed Postgres + a load balancer without touching route logic |

## 5. Local setup

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # edit SECRET_KEY / JWT_SECRET to random values

python seed.py                  # creates demo accounts + one assignment
python app.py                   # starts on http://localhost:5000
```

Open `http://localhost:5000` in a browser. Log in with:
- Teacher: `teacher@example.com` / `password123`
- Student: `student1@example.com` / `password123`

## 6. REST API summary

| Method | Endpoint | Role |
|---|---|---|
| POST | `/api/register` | public |
| POST | `/api/login` | public |
| GET | `/api/me` | any authenticated |
| POST/GET/PUT/DELETE | `/api/assignments[/<id>]` | teacher writes, any reads |
| POST | `/api/assignments/<id>/submit` | student |
| GET | `/api/submissions/me` | student |
| GET | `/api/assignments/<id>/submissions` | teacher |
| POST | `/api/submissions/<id>/grade` | teacher |
| GET | `/api/submissions/<id>/download` | owner student or teacher |
| GET | `/api/dashboard/student` \| `/api/dashboard/teacher` | respective role |

## 7. Upgrading to a real cloud backend

This is deliberately structured so each piece can be swapped independently:

- **Database:** change `DATABASE_URL` in `.env` to a managed Postgres
  connection string (Supabase, Neon, AWS RDS) — no code changes.
- **Object storage:** implement an `S3Storage` (or `FirebaseStorage`) class
  in `cloud/storage_service.py` with the same `save/absolute_path/delete`
  methods, and switch on `STORAGE_BACKEND`.
- **Deployment:** deploy `backend/` to a free-tier host (Render, Railway,
  Fly.io) and point `FRONTEND_ORIGIN`/`DATABASE_URL` at the hosted services.

## 9. Security notes for this build

- Passwords are hashed with Werkzeug's `generate_password_hash` — never stored in plain text.
- All non-public routes require a valid JWT (`Authorization: Bearer <token>`).
- File downloads check `_can_view()` — a student cannot fetch another student's file even by guessing a submission ID.
- File uploads are restricted by extension and by `MAX_CONTENT_LENGTH`.
- No secret is hardcoded; all sensitive config comes from `.env` (excluded via `.gitignore`).
